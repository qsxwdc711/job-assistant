# 求职助手 V1 产品与技术设计

日期：2026-10-14。依据：上一轮完整方案及用户关于权限、VIP 开通、飞书推送的明确选择。

本轮产物为设计和开发计划。本文定义后续实现行为，不代表功能已开发、数据已接入或云服务已开通。

## 1. 目标与边界

第一版帮助用户发现各行业的计算机相关岗位，区分已知投递条件是否满足，管理投递过程，每天通过飞书接收相关变化。

| 决策 | 首版约定 |
|---|---|
| 使用对象 | 先供本人使用，数据模型从开始支持多个独立账号 |
| 客户端 | 电脑网页和手机浏览器；微信小程序在后续阶段 |
| 岗位范围 | 各行业的计算机相关岗位，行业与岗位方向分别筛选 |
| 招聘类型 | 校招全职、实习、明确接受应届生或 0—1 年经验的社招 |
| 数据策略 | 官方来源优先，辅助渠道只用于发现线索 |
| 更新 | 每天一次，时区 Asia/Shanghai |
| 简历分析 | 本地提取文本，脱敏后允许云端模型进行语义分析 |
| 权限 | 管理员、VIP、普通用户 |
| VIP 开通 | 管理员手动授予或撤销，可指定到期时间或长期有效 |
| 通知 | 站内记录及用户指定飞书群的自定义机器人 |
| 部署 | 单台云主机、Docker Compose |
| 数据规模 | 首版以 20 家实际自动接入的公司为目标 |

不在 V1 中实现支付、自动代投、招聘平台账号托管、微信小程序、简历改写、扫描简历 OCR 和大规模全网爬取。

## 2. 用户操作路径

普通用户：登录 → 填写基础求职条件 → 筛选岗位 → 查看详情和官方入口 → 收藏或记录投递 → 订阅筛选条件 → 接收飞书摘要。

VIP：普通路径之外，上传简历 → 确认解析信息 → 指定当前使用的简历版本 → 查看岗位推荐、条件依据、技能匹配解释 → 接收个性化摘要。

管理员：创建账号和管理 VIP → 管理公共招聘来源、岗位和字典 → 查看采集及任务异常 → 按需查看用户数据 → 查阅敏感操作审计。

## 3. 权限与数据归属

角色值使用 `standard`、`vip`、`admin`。用户另外拥有可空的 `vip_expires_at`：VIP 且为空表示长期有效；VIP 且到期时间大于当前时间表示有效；到期后按普通用户能力判断。管理员不受 VIP 到期时间影响。

所有业务接口均要求登录；第一版由管理员创建账号，不开放公众注册。

| 行为 | 普通用户 | 有效 VIP | 管理员 |
|---|---|---|---|
| 浏览、筛选公共岗位和官方链接 | 允许 | 允许 | 允许 |
| 维护本人手动填写的基础求职条件 | 允许 | 允许 | 允许 |
| 收藏、投递记录、筛选订阅、飞书绑定 | 仅本人 | 仅本人 | 全部用户 |
| 上传、读取原简历、读取解析正文、确认解析 | 禁止 | 仅本人 | 全部用户 |
| 创建、读取简历推荐，个性化推荐推送 | 禁止 | 仅本人 | 全部用户 |
| 查看本人简历元数据、删除本人简历 | 允许 | 允许 | 全部用户 |
| 管理用户、角色、VIP、公共岗位和来源 | 禁止 | 禁止 | 允许 |
| 查看任务状态与通知结果 | 仅本人；不暴露推荐正文 | 仅本人 | 全部用户 |
| 查看审计记录 | 禁止 | 禁止 | 允许 |

普通用户的手动条件筛选不调用简历分析和语义推荐服务。前端隐藏按钮仅改善交互，后台的权限校验决定是否允许执行。

### 3.1 校验位置

请求处理依次检查有效登录、当前账号状态、角色能力、资源归属。个人查询以会话中的用户 ID 限定数据，不能相信请求参数中的 owner/user ID。

没有登录返回 401；角色无权使用功能返回 403；尝试访问其他普通/VIP 用户资源返回 404，避免透露该资源是否存在。

用户发起的私有后台任务保存原始 owner_user_id 和创建时的权限版本。领取、调用外部模型之前、落库和发送个性化通知之前重新校验当前权限、资源版本及资源是否被删除；不满足条件时任务标记 cancelled，不能借助旧任务恢复权限。

每日公共来源采集由系统调度身份执行，不继承任何用户的 VIP 权限；采集任务没有私有数据所有者。公共来源的暂停、重跑和配置修改仍仅由管理员操作。公共采集和用户任务使用不同任务类型，不允许客户端任意指定系统任务身份。

VIP 撤销或到期后，立即禁止新简历解析、新推荐及历史推荐正文读取。原数据保留，用户可以删除本人简历。新登录不会恢复已到期能力。

管理员可查看全部业务数据；查看、下载和删除简历，以及权限调整、账号禁用，记录操作者、目标资源、时间、动作、请求 ID。审计不记录简历正文、密码或密钥。

### 3.2 登录和文件

账号密码使用服务端哈希验证；密码不通过管理接口回显。服务端会话存储在 PostgreSQL，固定有效期默认 7 天，Cookie 使用 HttpOnly 和 SameSite，生产环境使用 Secure，写操作校验 CSRF。

每个设备可拥有独立会话，角色和禁用状态从服务端读取。初始化管理员通过部署命令创建，不在公开 API 中提供自助管理员注册。

S1 实现约定：bcrypt cost 12，32 字节随机会话令牌仅存 SHA-256 摘要；CSRF 使用会话令牌与独立服务端密钥的 HMAC，登录和当前用户接口返回 CSRF 值。账号/审计读取及管理写入均在事务中复核当前操作者权限；敏感写入与审计原子提交。最后一个启用的管理员不得停用或降级。停用会删除全部设备会话，重新启用不会恢复旧会话。

原简历保存在非公开持久化目录，下载经鉴权接口处理。删除简历会使关联解析、推荐和待执行任务失效并删除对应内容；投递记录保留，但移除其对已删除简历的关联。

## 4. 公共岗位与筛选

岗位方向初始包含后端、前端、移动端、嵌入式、测试、运维/SRE、网络安全、数据、算法/AI。专业、方向和行业使用可扩展字典，不把“计算机”写死在采集器或基础表结构中。

筛选项包括专业、岗位方向、行业、企业性质、地点、企业标签、毕业届数、招聘类型、笔试状态、公司名称、岗位关键词和截止日期。

- 国内地点使用省份、地级市编码；海外使用国家/地区与城市。一个岗位允许多个地点。
- 央企、国企、事业单位、外企、民企作为企业性质。“一线大厂、冷门大厂、行业翘楚、腰部名企、中小厂”作为管理员维护的标签，保留标注依据。
- 专业要求允许明确专业、专业大类、相关专业、专业不限、未披露。无法证明“相关专业”包含本人专业时标记待确认。
- 毕业届数是界面入口，底层保存真实毕业时间范围与国内/海外、学历等适用条件；不只保存一个年份。
- 实习额外记录在校身份、可开始时间、最短持续时间和每周出勤要求；“某届优先”归入偏好，不改写为只允许该届。用户未确认出勤或时长时为待确认。
- 笔试状态为 yes/no/unknown。只有明确无笔试的适用官方证据才能标为 no，未提到笔试为 unknown。
- 截止日期为空表示未公布。只写日期时按该来源明示时区当天结束处理，并保留“由日期推导”的标记；时区无法确认时进入待确认。
- 明确要求经验超过 1 年且不接受应届/低经验候选人的社招不进入本版主库。经验未披露的社招进入待核实队列，不自动当作可投岗位。

列表与表格使用相同 API 和筛选条件，筛选状态保存在 URL，保存的订阅条件存服务端。默认按最近更新降序，允许按截止时间排序，未公布截止的岗位排在已知截止之后。

每条已发布岗位必须具有可核查的官方出处和投递入口，并显示链接级别为岗位直达、批次入口或公司入口。官方入口需要登录时可以保留链接，但标明需要登录。没有官方依据的线索只在管理员待核实队列中展示。

公开岗位状态为 open/closed/unknown，核验状态另外存储。网络错误、登录墙、验证码、一次列表缺失不能直接产生 closed；明确截止、官方关闭或针对该适配器验证过的“已结束”证据才能关闭。

## 5. 官方来源和每日更新

每家公司可以拥有多个来源和招聘主体。公司名相同不代表同一岗位；分行、子公司、不同招聘批次的适用条件必须保留。

采集优先级是公开结构化数据、HTML、动态渲染。浏览器只用于必要的公开页面，限制并发；登录或验证码受限来源标记 restricted，不自动绕过验证。

公司官网直接链接的第三方招聘服务商页面可以作为官方授权来源，保存官网到服务商的授权链。搜索结果和论坛贴只用于找到官网，不作为开放状态的依据。

每日 08:00 创建采集批次，按来源执行并记录运行结果。相同来源、日期、任务类型具有唯一调度键，服务重启后恢复未完成工作。

来源提供岗位 ID 时使用“来源+岗位 ID+招聘批次”识别记录；没有 ID 时使用稳定详情链接和批次。跨来源自动合并仅在明确具有同一官方标识时执行，名称相似只生成管理员重复候选。

保留公开详情的必要证据、内容哈希、采集时间和标准化结果。检查内容变化时忽略页面装饰，重要变化包含条件、地点、截止和状态变更。查询时重新判断明确已过的截止时间，避免列表出现过期可投岗位。

2026-10-14 的 S0 实测要求保留招聘广告与实际岗位子方向：华为广告详情可能只有占位文字，真实职责、条件及部门城市关系在岗位意向接口。标准岗位可包含多个 source_variants，每个方向的职责、条件、部门和城市成组保存。匹配分别判断方向，并显示确切的方向与城市；不能拼接方向 A 的条件和方向 B 的地点生成可投结论。

腾讯当次父菜单毕业范围与具体 2027 子批次不一致。菜单层展示文字不能自动继承为岗位门槛；需要先确定当前实际批次及证据适用范围。共同适用的有效条件才取交集，明确过时的菜单显示文案单独保留并标注。

招商银行的公告和具体岗位为两个资源，分别保存公告 ID、岗位 ID、招聘主体、条件及状态。公告仍可读取但已超过其截止时间时不能标为开放；具体列表成功空结果不能用于断言全部校招关闭。

20 家目标及源验证步骤见 [来源验证清单](../../research/2026-10-14-source-validation.md)。完成数量按实际自动接入统计，人工维护和未验证来源单独展示。

## 6. 简历解析与推荐

输入格式为 PDF、DOCX，单文件最大 10 MiB。验证扩展名、实际文件类型、提取结果和 DOCX 解压大小；拒绝加密、扫描、损坏或无法可靠提取文本的文件，说明重新上传方式。

在服务器本地提取文字。调用模型前移除姓名、手机、邮箱、证件信息、详细住址等直接身份信息，仅传必要教育、技能与经历文本。学历、学校、专业、毕业时间和履历仍可能具有识别性，上传页明确披露脱敏范围及外部处理用途，不宣称完全匿名。

模型提供结构化解析草稿。缺失信息留空，用户确认后才形成用于推荐的 profile_version。多个简历版本允许保存，每个用户同时选择一个当前版本。

岗位匹配分两层：

1. 硬性条件由规则引擎判断，返回 eligible、needs_confirmation、ineligible。保留批次与岗位条件；共同适用的条件取交集，相互矛盾或不明确时进入待确认。学历、毕业时间、专业、学生身份、明确经验要求等逐项提供原文依据。
2. 语义匹配只对非 ineligible 的岗位执行，给出 high/medium/low、支持证据和差距。必需与优先条件分别解释，简历未写某技能不等同于明确不会。

eligible 的界面含义是“满足已知投递条件”，不表示一定通过企业筛选。不展示面试通过概率，不让模型覆盖明确的硬性不满足结果。

默认使用 DeepSeek 云端适配器，供应商与模型由部署配置指定。模型输出经 JSON 结构和引用证据校验，引用必须指向输入的简历/JD 内容，不允许生成凭空的能力、经历和岗位条件。

推荐缓存键包括用户、确认后的 profile_version、job_version、规则版本和模型配置版本。简历或 JD 修改后旧结果标记 stale，不能当作新结果发送；模型超时或输出错误保留规则判断，语义状态为 failed，允许有界重试。

存在子方向时缓存和结果额外保存 source_variant_id 与该方向内容版本。父岗位可以汇总存在匹配方向，但不能宣称该广告所有方向、部门或城市都满足条件。

用户更换当前简历后，已有投递关联仍指向当时的简历版本，后续推荐使用新版本。已投递或用户明确结束的岗位不再次作为待投机会推送。

## 7. 投递管理

状态为 draft、submitted、written_test、interview、offer、rejected、withdrawn。用户可以手动修正状态，不假设所有公司都按固定阶段顺序招聘。

同一用户、同一岗位只存在一个主投递记录。保存状态变更历史、备注、下一步事项、事项时间，以及可空的投递简历版本。

公共岗位关闭不删除个人记录，也不自动标为拒绝。多设备编辑使用 version 字段；版本冲突返回 409，并提示刷新后修改，避免静默覆盖。

## 8. 飞书和站内通知

每个账号绑定一个默认飞书自定义机器人接收配置，保存 Webhook、签名密钥和启用状态；配置只属于该账号，不隐式复用管理员的群。

只接受合法的 HTTPS 飞书 Webhook 地址。Webhook 和签名密钥加密保存，API 不回显完整密钥，日志脱敏。每次发送都按当前账号权限生成内容。

每日 09:07 生成摘要：使用已完成来源的结果，未完成或失败来源在站内显示，不能宣称全部来源已更新。后续完成的采集结果进入下一次摘要，管理员可显式重跑该次摘要。

普通摘要按保存的筛选订阅产生；个性化摘要必须使用有效 VIP/admin 权限和当前简历的有效推荐。没有相关事件时不发送。

截止窗口为 7 天、3 天、1 天。每个窗口最多形成一个事件，用户首次订阅已在窗口内时只提醒最近的适用窗口，不在同一天补发三个窗口。

群消息仅含公司、岗位、地点、截止、条件待确认标记、官方入口和需登录的网页详情链接。身份信息、简历原文、技能差距和个人投递备注不进入群消息。

内容优先级为 1 天截止、3 天截止、7 天截止、重要变更、新机会。摘要最多显示 10 个唯一岗位，总体以 18 KiB 为内部预算，剩余数量链接到网页；还需验证最终 JSON 的实际字节长度。

使用持久化通知发件箱。事件键包括用户、岗位、事件类型和对应内容版本/截止窗口；批次键包含用户、日期和接收配置。重试复用同一发件箱记录。飞书 HTTP 200 仍需检查业务返回码；明确拒绝或限流时最多三次尝试并退避，网络超时导致送达状态不明时标为 delivery_unknown，留给管理员确认，避免盲目重发。

通知事件、发送记录保留站内。账号停用、配置关闭或个性化权限失效时取消尚未发送的相关通知。

## 9. 技术和数据边界

### 9.1 部署

Go 使用 net/http，数据库驱动采用 pgx；网页使用 Vue 3、TypeScript、Vite、Vue Router、Pinia。数据存储为 PostgreSQL 18，全文及关键词筛选先采用 PostgreSQL。

同一后端代码构建 api、worker、管理初始化命令。worker 执行持久化任务，任务领取使用 PostgreSQL 行锁/租约；不在 HTTP 请求中同步采集或等待模型。

单台云主机上的 Docker Compose 提供 API、worker、PostgreSQL、HTTPS 反向代理和持久化目录。网页构建产物与 API 使用同源入口。浏览器采集默认最大并发 1，普通采集最大并发 3，同一域名最大并发 1。

初始化时锁定 Go、Node、数据库镜像及依赖版本；备份包含数据库和必要文件，密钥单独保存。后端模块按业务职责组织，不为首版引入微服务、Redis、消息中间件或 Elasticsearch。

### 9.2 核心数据

| 数据组 | 内容和必要约束 |
|---|---|
| users、sessions | 角色、VIP 到期、权限版本、禁用状态；会话归属和过期 |
| companies、sources、campaigns | 公司与招聘主体、授权链、采集器类型、批次和通用条件 |
| jobs、job_versions、job_variants、job_locations、job_tags | 官方标识、广告与方向父子关系、成组条件/部门/地点、来源证据及版本 |
| profiles、resumes、profile_versions | 手动求职条件、私有文件、待确认/确认后的解析版本 |
| recommendations | 用户、简历与岗位版本、逐项条件结论、语义状态和证据 |
| applications、application_events、favorites | owner_user_id、岗位关联、版本冲突控制及历史 |
| subscriptions、notification_channels、notification_events、deliveries | 用户订阅、加密接收配置、事件去重和投递状态 |
| tasks、source_runs、audit_events | 幂等调度、租约与重试、来源结果、敏感操作日志 |

每个用户私有资源都有 owner_user_id；管理接口和个人接口分开。复杂招聘条件采用有版本的结构化规则数据，保留原始文本，未知值不能替换为 false 或空条件。

### 9.3 API 分组

统一前缀为 /api/v1，日期时间传输使用 RFC3339，数据库时间使用 timestamptz。

| 分组 | 主要行为 |
|---|---|
| /auth | 登录、退出、当前用户和权限能力 |
| /jobs | 分页筛选、岗位详情、来源及核验状态 |
| /me/profile、/me/favorites | 本人手动条件和收藏 |
| /me/applications | 本人投递记录、历史、备注、事项 |
| /me/resumes | 上传、解析任务、确认、选用版本、鉴权下载、删除 |
| /me/recommendations | 创建任务、读取有效版本结果和解释 |
| /me/subscriptions、/me/notification-channel、/me/notifications | 订阅、飞书绑定、站内结果 |
| /me/tasks | 读取本人任务状态，禁止跨用户结果泄露 |
| /admin | 用户/VIP、公司、岗位、来源、任务、审计和全部用户数据 |

列表分页默认 20、最大 100。异步创建返回 HTTP 202 和 task_id，任务状态为 queued/running/succeeded/failed/cancelled。统一错误包含稳定 code、可读 message 和 request_id，不返回堆栈、SQL 或密钥。

普通用户删除过往简历属于保留的隐私控制能力，不代表允许使用 /me/resumes 下的其他 VIP 功能；授权按动作判断。

岗位详情返回实际存在的子方向与部门城市关系；推荐结果注明具体方向。公告、广告或菜单文案不冒充一个完整的可投递单元。source_external_id 使用字符串保存，避免腾讯大整数 postId 经 JavaScript Number 精度丢失。

## 10. 验收和扩展

开发与验收阶段见 [实施计划](../plans/2026-10-14-job-assistant-implementation.md)。三类来源取得真实、可重复的详情是应用开发前的第一项验证。

最终要求：20 家实际自动接入，连续 7 天完成每日任务调度；失败情况可追踪，不因失败删除岗位；权限矩阵和所有私有资源通过越权测试；简历条件判断有原文依据；飞书发送按用户和当前权限隔离；电脑/手机形成完整投递闭环。

其他行业扩展增加专业、行业、岗位方向字典、适用规则和来源；保留通用的岗位、权限、推荐、投递及通知接口。微信小程序作为后续 API 客户端接入。
