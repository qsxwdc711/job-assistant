# 当前页岗位个人状态修复设计

修复范围为 F-01、F-02：个人收藏或投递超过 100 条时，岗位看板和收藏页必须仍显示正确的操作。用户已要求修复上述问题。

## 方案

新增 `GET /api/v1/me/job-states`，使用可重复的 `job_id` 参数，一批接受 1–100 个 UUID。响应只含 `job_id`、`favorite`、`recorded`。用户归属来自当前会话；管理员访问也仅查询自己的状态。未知 ID 以两个 false 返回，隐藏岗位仍可查询本人保留的状态。

HTTP 层校验 UUID 和批量大小，application 层复用事务内的当前账号复核。SQL 以请求数组及 ordinality 保留顺序，通过既有 `(owner_user_id,job_id)` 索引查询存在性，不需要数据库迁移。

Vue 页面先读取当前页岗位，再查询这些岗位的个人状态。列表与状态作为同一次逻辑请求完成后统一展示；旧 route 请求的结果及错误被 requestID 拒绝。状态加载失败时显示可重试错误，避免用户操作尚未确认的状态。

## 取舍

每次翻页读取全部个人列表会使开销随记录总数增长；本方案将批量大小限制为当前页。把个人状态加进公共 catalog 类型会耦合公共岗位与私有记录；独立 `/me` 查询保持现有包边界。

## 验收

- 106 个收藏的末页六条均显示取消收藏，一次点击即移除，随后五条状态仍正确。
- 106 条投递的看板 100 个岗位均显示查看进度，进入进度页不发重复 POST。
- HTTP 验证普通/VIP/管理员本人隔离、伪造 owner 无效、非法与超量输入、未知与隐藏岗位、停用后拒绝访问。
- 延迟上一轮状态响应不能覆盖后一次搜索；状态请求失败后可重试。
- 原有跨设备编辑冲突、全部功能测试、Go race/vet/gofmt、前端构建通过。本机持久数据保留。
