# 219 项指定企业岗位录入设计

## 范围

用户于 2026-10-22 给出六组共 219 个目标，并已确认沿用原范围：计算机相关校招、实习，以及明确接受应届或最多一年经验的社招。原始名称、分组和稳定 target_id 保存在 `docs/research/targets/2026-10-22-requested-companies.json`。其中汽车新能源 40、中小厂 34、国企 24、游戏 38、快消 50、外企 33。

本批不设置新的 20 家上限；原首版 20 家目标保留为历史里程碑。219 是用户目标条目数，不等同于独立招聘主体数。韶音复用既有公司和来源；腾讯天美 T1、华为车 BU、TapTap 等按官方主体和实际岗位归属核实，不能复制整个母公司岗位来填满子目标。

## 接入方式比较

| 方式 | 结果与取舍 |
| --- | --- |
| 建议：按平台批量接入，逐家验证授权和岗位条件 | 能复用分页、字段归一化和每日更新；每家公司仍保留独立证据和状态 |
| 逐岗位人工录入一次快照 | 可先录少数静态公告，但后续变动要人工维护，不能当自动接入 |
| 聚合平台批量导入 | 便于发现线索，但本项目仍须回到官方详情核实，不能替代官方溯源 |

## 建议方案

沿用现有 S5 官方来源→完整读取→校验→原子发布→定时更新流程，增加经过官方授权链验证的 Moka 租户配置，并接入本批大量企业共同使用的飞书招聘公开岗位接口。北森、大易、Workday、自建站等分别按真实合同接入；登录、验证码或无法确定主体的条目保持明确待核实状态。

全清单与各调研分表作为覆盖台账，逐项区分待验证、官方入口已核实、岗位详情已核实、采集适配已验证、实际已发布、公开受限和成功读取但无本版候选；不能将入口线索写成岗位入库成功。各平台完成后先通过测试，再分批发布到现有本地看板。已验证的来源继续每日更新。

### 已取得的实际合同依据

- 博世中国官网 careers 页直接授权 Moka `bosch/168626`（2027 站）与 `bosch/73873`，公开查询已确认 campus 模式、`jobs/v2`，分别有 166 与 25 条列表广告；须逐条核实技术范围和届数，不能把全列表算作技术岗位。
- 拓竹公开校招页在独立无登录浏览器中实际调用 `POST /api/v1/search/job/posts`，请求包含 limit/offset、portal_type=6、portal_entrance=1 和公开筛选条件。成功业务码为 0，响应有 job_post_list 和 count，本次公开列表总数为 168。前端、后端、移动端实习与非技术职位同时出现，证明必须筛选，不能直接整站导入。
- 飞书页面正常使用匿名 cookie 与公开 CSRF 初始化。仅使用这些公开会话能力，不读取申请人账号、登录状态或候选人接口，不复用个人 Cookie，不绕过验证码。
- 多家公司通过官网授权同一平台，支持按合同复用；来源域名和租户必须使用固定白名单，不能接受任意 URL。

### 数据规则

岗位保留官方 ID、招聘主体、招聘批次、标题、职责、要求、地点、招聘类型、学历、专业、届数、实习出勤/时长、笔试与截止依据、官方详情和投递入口。缺失字段维持 unknown，明确条件与优先条件分开。Moka 自定义字段中的学历、经验及届数不能丢失；例如博世详情存在独立“工作经验要求：1 year”字段，必须进入资格原文和匹配依据。

飞书使用官方 recruit_type、job_subject 等结构化字段确定招聘类型与批次，并核对列表、详情及页面身份。读取完整分页，验证总数稳定、ID 唯一、无短页或晚到错误；接口显示的时间戳和追踪信息不制造内容版本。完整成功后一次发布；失败、受限和缺失不关闭旧岗位。

用户分组保留原名，但不自动转换成未经核实的企业性质或“中小厂”规模标签。实际行业沿用可扩展字典并记依据；一家公司可服务多个目标名称，不据名称相似自动合并岗位。

### 验收与发布

- 全 219 项名单数量、名称、分组、ID 唯一性检查；台账不允许遗漏或把 pending 当完成。
- 每个新增租户至少两次独立完整读取，记录公开证据、候选数、排除原因和稳定身份/文档哈希。
- 单元测试验证分页完整性、类型冲突、非技术排除、实际隐藏资格字段、偏好与硬条件、详情错误及受限停止。
- 专用 PostgreSQL 验证新来源发布、重复不增版本、失败不部分发布、既有数据隔离、来源暂停和权限；运行 gofmt、go vet、Linux race 和相关既有回归。
- 验证镜像构建、迁移、就绪、正常关闭；电脑和手机确认新增公司筛选、实习与官方链接。生产前备份并比对旧岗位/版本、私有数据与配置，清理独立测试资源。
- 飞书消息继续模拟，不向真实群发送。来源受限及未完成工作如实记录，不把全部目标已经登记成清单说成所有岗位已录入。
