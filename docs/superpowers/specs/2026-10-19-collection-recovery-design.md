# S5 采集失败后的当日自动恢复设计

## 问题与目标

2026-10-19 早间九个定时采集任务均在三次网络错误后结束。下午通过现有管理员接口逐个补采成功，历史失败记录保留。这说明当前机制不能覆盖持续数十分钟的网络故障；补采成功也不能证明原网络故障已经解决。

本次目标是在电脑、数据库和 worker 正常运行的前提下，为当天自动采集增加有限恢复机会，保留完整失败记录、来源访问边界和现有通知截止规则。恢复能力通过独立 PostgreSQL 中的可控故障验收，不以真实企业官网反复失败作测试。

## 方案比较

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| 建议：保留三次尝试，增加两轮延迟恢复 | 原任务结束；另建有父任务的恢复记录，分别等待 30 分钟、2 小时 | 能处理较长中断，次数有上限，历史清楚；需要队列元数据和相应检查 |
| 提高单个任务尝试上限 | 一个任务持续重试 | 修改较少，但弱化现有三次约束，难以区分原失败和恢复，仍须定义全天上限 |
| 维持管理员手动补采 | 失败后由人决定何时再次更新 | 无额外自动请求，但用户不在电脑前时无法自行恢复 |

## 建议的执行规则

1. 每天北京时间 08:00 后的原始 daily 任务保持不变，每个任务最多三次尝试，任务内退避仍为 1、4 分钟。
2. 仅当当天的自动任务以 `network_error`、`timeout`、`timeout_or_cancelled`、`source_busy` 或 `interrupted` 耗尽三次尝试，才允许建立下一轮恢复任务。第一轮距原任务最终失败至少 30 分钟；第二轮距第一轮最终失败至少 2 小时。单个来源每天最多原任务加两轮恢复，共九次任务领取；HTTP 客户端现有的单次读取重试不因此扩大。
3. `restricted`、登录要求、结构或校验变化、发布错误、暂停、取消，以及不能确认错误类别的 `attempts_exhausted` 不自动进入新一轮。第三次领取后进程失联且租约过期的情况仍保留原有失败行为，不能据此假定是网络错误。
4. 当天 22:00 起停止新增恢复任务；恢复任务不能跨北京时间日期重新开始读取。午夜前已开始的读取可以在原有超时和租约边界内结束。
5. 同一个来源、日期、轮次使用唯一调度键。重启和多个调度实例不能生成额外轮次；关闭自动调度时不创建恢复任务。
6. 若来源在父任务失败后已经由定时、管理员或 CLI 成功更新，则不再为该失败补采；已经排队的恢复任务领取前也须重新判断并取消。存在该来源其他待执行或运行中任务时，恢复任务等待其结果，避免紧随手动任务重复读取。
7. 领取恢复任务前重新检查来源开关、父任务状态、最新成功时间和较新的访问受限或非暂态失败。恢复计划不能越过后续访问限制；运行期间继续沿用发布前来源开关检查。
8. 使用原有共享队列、域名互斥、全局最多三个读取、租约和 token。Docker worker 与 Windows public worker 仍仅领取各自负责的来源，不能改变权限或接触简历处理。
9. 09:07 摘要截止线保持不变，迟到岗位留给后续摘要。飞书保持模拟模式。恢复记录在现有管理页可见，不增加默认通知或真实发送。

## 数据与代码边界

为 `scheduled_collections` 增加可空父任务引用和恢复轮次，数据库约束轮次为 0–2，原任务为 0 且无父任务；恢复任务保留父任务引用，每个父任务只能有一个子任务。原任务、失败次数与错误码不重置。使用现有唯一调度键编码日期、来源和轮次，创建及领取时核验其当天范围和完整父链；非法元数据不能触发读取。

队列恢复计划和领取前检查放在 `backend/internal/task`，供既有 automation 和两种运行环境共用。调度器只负责调用计划；不在启动脚本里另建网络探测或补采循环，不直接修改生产任务状态。数据库查询必须防止并发重复计划，并在领取事务中完成取消或等待判断。

不增加企业来源、不更改匹配规则或用户权限。本次完成后再继续扩源，避免把恢复策略验证与新官网访问问题混在一起。

## 验收要求

- 专用 PostgreSQL 验证 08:00 与 22:00 边界、30 分钟与 2 小时间隔、两轮上限、跨日停止、重复及并发调度幂等。
- 覆盖每种允许错误、受限与结构变化禁止恢复、尝试未耗尽、未知租约耗尽、暂停及禁用调度。
- 验证管理员或 CLI 成功后不再补采，较新受限结果阻止恢复，已有排队/运行任务先执行；父任务失败历史不被重写。
- 验证恢复成功不增加相同内容版本，失败不发布部分岗位；Docker 与原生队列视图仍隔离来源并共享租约。
- 运行 gofmt、go vet、Go 测试及 Linux race；恢复等待不阻塞摘要、正常关闭和已有权限/通知检查。测试使用模拟读取与独立数据，清理本次资源。
- 部署前备份、记录旧任务及数据计数；验证迁移、镜像、服务就绪与运行配置，保留真实飞书关闭。实际长时间离线、连续七天及云端验收仍单独记录，不能用时间推进测试代替。
