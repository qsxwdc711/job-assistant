## 本机运行差异及增补

Windows 的三次完整读取成功，Docker 中相同来源的 Go/curl、直连及现有代理均出现 TLS EOF；降低混合密钥交换也没有改善。未绕过证书验证。临时 TCP 转发诊断服务的启动被自动审批以 blocked by policy 拒绝，服务未启动，停止该方案。

继续沿用已批准的系统公共采集身份和持久队列，采用可选本机公开采集进程，而不是网络转发服务。该进程只领取配置的来源；容器按配置排除这些来源，仍统一排每日任务并生成摘要。所有运行时继续共享域名锁、全局三个读取上限、租约、重试、暂停和更新结果。未配置时保持全部由容器读取。

- [ ] `CollectionStore.WithSources` 仅过滤领取，不改变全局计划与恢复；实际 PostgreSQL 验证两种运行时领取范围、配置快照和中断重试。
- [ ] `cmd/public-worker` 只消费明确允许的公共来源，使用信号或本机停止标记关闭；初始化有十秒预算，不加载简历、模型、飞书或私有任务。
- [ ] `start-host-collector.ps1` 根据本机配置构建/启动自己的进程，按 PID 与可执行路径核对后正常停止，不强杀其他进程；凭据仅通过环境继承，不写命令行或日志。
- [ ] 独立 PostgreSQL 绑定 loopback 测试端口，实际构建 Windows 进程、启动并正常关闭；本机正式来源再验证自动领取与完整入库。
- [ ] 本机仅为中久设置 COLLECTOR_HOST_SOURCES；其余来源仍由 Docker 处理。说明需保持该本机进程运行；云端该来源网络仍待验证。
