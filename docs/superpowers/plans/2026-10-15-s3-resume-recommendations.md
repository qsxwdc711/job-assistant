# S3 简历与岗位推荐实施计划

**Goal:** 交付 VIP/admin 私有简历上传、本地提取与脱敏预览、模型解析草稿与本人确认、按方向的资格与技能解释，以及撤权/删除/版本变化后的任务阻断。

**Architecture:** 在现有 Go 单体内增加 profile、matching、task、llm、workflow 包和独立 worker 入口。PostgreSQL 保存不可变资料版本、推荐缓存与带租约的任务；原文件使用私有目录。HTTP 不等待模型，模型调用前后重新检查当前权限、资源和版本，页面轮询任务及结果。

**Tech Stack:** Go 标准库、pgx、Poppler、本地 DOCX XML 提取、DeepSeek HTTP JSON 输出、Vue、PostgreSQL、Docker Compose。

## 设计与验收约定

- 沿用既有 S3 产品设计；不开展 S4 的每日招聘调度与飞书业务。
- PDF/DOCX 最大 10 MiB，文件签名与扩展名一致，DOCX 解压有总量限制；加密、扫描、损坏文件明确失败。Poppler 在生产镜像中安装并记录版本。
- 上传先进行本地处理，用户查看脱敏文本后显式同意外部处理，才创建模型解析任务。姓名、电话、邮箱、证件和详细地址移除；姓名补充用于全文移除，不宣称完全匿名。没有密钥显示未配置；允许用户手工填写确认资料以使用规则结果。
- 草稿不参与推荐；确认生成不可变 profile_version。切换当前版本使旧任务取消、旧结果 stale；删除使文本/版本/推荐失效并清理原文件，个人投递保留。
- 按真实岗位子方向计算学历、毕业范围、专业、经验、学生身份及实习出勤/时长。明确不满足不调用语义模型；含糊条件进入待确认。“优先”不作排除条件。
- 语义输出只允许 high/medium/low，必需与优先分开；简历/JD 引用必须确实存在。超时或坏输出保留规则结果，不编造成功或录用概率。
- 缓存包含 owner、资料版本、岗位版本、方向内容哈希、规则和模型配置版本；普通账号不能读取正文/推荐，仍可删除本人过往简历。管理员跨账号操作审计不含正文。
- worker 使用独立租约、最多三次有界重试、过期领取；回写验证租约令牌，避免旧 worker 发布结果。任务 payload 只保存 ID。
