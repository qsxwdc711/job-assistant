# S4 定时更新、订阅与飞书运行说明

本轮按用户选择采用模拟验收，`NOTIFICATIONS_SEND_ENABLED=false`。模拟完成会保留站内记录，状态为 `simulated`，不会请求真实飞书机器人。真实群送达需要后续单独验收。

## 使用方式

打开网页的“订阅通知”（`/notifications`），填写岗位方向、专业、行业、企业性质、规模、城市、届数、招聘类型、关键词、笔试和截止时间等条件，保存并启用订阅。每个账号各有一份订阅和一个默认飞书接收配置。

- 普通账号可以按保存的筛选条件订阅。筛选结果用于发现机会，不能替代官方资格确认。
- 有效 VIP 或管理员可以选择当前简历的有效匹配结果。先在“岗位匹配”评估岗位；缺失或过期的推荐不会退回普通筛选。规则判断为满足已知条件或条件待确认的方向才会入选，明确不满足的方向排除。未配置模型时，成功生成的纯规则结果可以使用。
- 第一次启用会纳入已有的匹配机会；之后记录新机会、实质条件变更和临近截止。个性化推荐在空摘要之后才就绪，或切换当前简历后首次出现的匹配机会，会进入后续摘要。已通知的同一内容不会每天重复提醒。
- 不配置飞书也能使用站内摘要，显示“仅站内通知”。没有新事件的批次显示“本次没有新机会”，不排队发送空消息。
- 管理员可以更新选中来源、立即生成摘要，并在发送记录中显式选择账号。页面列出前 100 个账号，更多账号可用带 `owner_user_id` 的管理接口分页读取；不会隐式改用管理员自己的接收群。

飞书地址与签名密钥是只写字段，保存后清空输入框。留空保留原值；要移除全部配置使用“清除接收配置”。机器人若启用关键词校验，关键词需包含“求职助手”。连接测试只发送固定测试文案；模拟模式下连固定文案也不发到真实群。

## 时钟与持久化任务

时间采用北京时间（UTC+8）。worker 每 30 秒检查调度，在 **08:00** 后为当天每个启用来源创建一个唯一任务；重启补当日任务，不无限补历史日期。当前是八家企业的十个来源，包含校招、实习和经逐条核实的低经验岗位。

采集使用三个独立循环，同域名最多一个实际读取，全部入口（自动、管理员排队和 CLI）合计最多三个读取。域名和全局限制由 PostgreSQL advisory lock 共享。队列采用行锁、20 分钟租约和随机 token；实际采集请求最长 15 分钟，外层处理最长 17 分钟。过期的旧 token 不能结束新的任务。网络或超时、域名忙和正常关闭中断可退避重试，最多三次；格式变化或访问受限不会密集重试。暂停来源取消待执行或已过期的任务；正在执行的采集还会在发布前检查来源开关。

### 同一天的有限自动恢复

2026-10-19 起，自动采集耗尽三次尝试且最后错误为 `network_error`、`timeout`、`timeout_or_cancelled`、`source_busy` 或 `interrupted` 时，可在当天再建立两轮恢复任务：第一轮距原任务最终失败至少 **30 分钟**，第二轮距第一轮最终失败至少 **2 小时**。每个任务仍最多三次尝试；单个来源每日自动预算最多九次任务领取。各采集器内部原有的有限 HTTP 重试仍独立适用。原失败任务保留，恢复任务用独立 ID、父任务引用和轮次记录，不能把原任务重置成成功。

北京时间 **22:00 起不新增恢复任务**。已排队恢复任务可在当日执行；跨日不再开始，已经运行的读取按原租约和超时结束。每日任务的 08:00 补计划规则不受 22:00 限制。`AUTOMATION_ENABLED=false` 不计划恢复任务。

已由管理员或 CLI 成功更新的来源停止对应恢复，已排队任务在领取前取消。存在同一来源其他待执行/运行任务或较新的 CLI 读取时，恢复等待其结果。较新的访问受限、结构变化或其他非暂态失败会阻止恢复；来源暂停时仍取消工作。无法确定原因的第三次租约耗尽（`attempts_exhausted`）不进入新一轮。唯一调度键及每个父任务唯一子任务约束共同限制重复计划，Docker 与原生公共进程使用同一策略。

管理员采集历史会保留新增任务及其最终状态。数据库中 `recovery_round=0` 表示原有任务，1、2 表示恢复轮次；`recovery_parent_id` 指向前一失败任务。恢复取消码包括 `recovery_superseded`（已补采成功）、`recovery_source_blocked`（较新结果阻止）、`recovery_expired`（跨日）和 `recovery_parent_invalid`（日期键或父链不符合规则）。`source_paused` 仍表示来源暂停。它们不表示旧岗位已关闭。

该机制提供有限恢复机会；整个恢复窗口持续断网时，仍需管理员补采或等次日任务。电脑、Docker 或 worker 未运行时无法执行，需要常驻运行环境提供可用性保障。设计与验收见 [恢复设计](../superpowers/specs/2026-10-19-collection-recovery-design.md)和[本轮记录](../verification/2026-10-19-collection-recovery.md)。

**09:07** 之后，摘要使用 `job_versions.created_at <= 当日09:07` 的版本。来源运行结果同样按截止线记录为成功、失败、受限或未完成。迟到的岗位版本留给后续摘要；管理员“立即生成摘要”使用该次请求时间作截止，可显式纳入迟到结果。采集、摘要、通知发送和原有简历处理分别运行，慢官网不会挡住摘要循环。

电脑、Docker 和 worker 持续运行才会执行到点任务；休眠或关机时没有外部服务代跑。到点后的首次运行会补当日工作。连续多日稳定性和云端常驻运行属于后续验收。

## 配置与密钥

`.env` 是 Git 忽略文件，不要把内容提交或复制到聊天中。新环境初始化会生成独立的 32 字节随机 `NOTIFICATION_KEY`；已有环境保留原数据库密码、管理员密码、CSRF 和模型设置，只增加缺失的新配置。

| 设置 | 含义 |
|---|---|
| `NOTIFICATION_KEY` | Base64 编码的 32 字节 AES-256-GCM 密钥；与数据库分开备份，丢失后无法解密旧群配置 |
| `NOTIFICATIONS_SEND_ENABLED=false` | 默认模拟模式；API 和 worker 必须使用一致配置 |
| `AUTOMATION_ENABLED=true` | 开启每日规划与摘要；false 仍会处理显式排队的任务 |
| `APP_ORIGIN` | 网页的同源入口，用于消息内站内详情链接；生产使用 HTTPS |
| `COLLECTOR_HTTP_PROXY` / `COLLECTOR_HTTPS_PROXY` | 可选 worker/CLI HTTP 代理；Docker 中访问宿主机代理需使用 `host.docker.internal` |

没有加密密钥仍可生成站内摘要，但保存群配置返回 `503 notification_not_configured`。配置更改后使用 `./scripts/start-local.ps1 -SkipBuild` 重建容器配置并重新创建 API/worker。已有密钥不能当作密码随意重新生成；需要轮换时先停止发送，备份密钥和数据库，并重新绑定受影响的接收群。

本轮保留模拟开关。后续验收真实群时，由本人绑定机器人并主动触发连接测试，再核对业务返回、实际群消息和接收账号；配置真实机器人、打开开关或发送测试均不在本轮自动执行。

## 消息与失败处理

消息只含公开岗位公司、名称、对应方向地点、明确截止、条件待确认标记、官方入口和需登录的详情链接。不含用户名、简历正文、推荐解释、技能差距或投递备注。纯文本中的 `<at ...>` 标记会被转义。

一个广告合并显示一次，排序为 1 天、3 天、7 天截止、重要变更、新机会；最多显示 10 个广告。最终含签名的 JSON 逐字节检查，不超过 18 KiB；超出部分留总数和站内链接。截止只使用明确的 `deadline_at`，首次进入多个窗口时只采用最近的窗口。

发送之前重新检查当前账号、订阅与接收配置 revision、VIP、当前简历、岗位版本和有效推荐。已投递（除 draft 外的状态）、已隐藏、明确结束或过期的项目会移除；整批没有有效项目时取消。群配置加密保存且按所有者绑定，接口及审计不返回凭据。

| 状态 | 行为 |
|---|---|
| `queued` / `sending` | 等待处理 / 已提交一次发送尝试 |
| `simulated` | 本地模拟完成，没有向群发请求 |
| `sent` | HTTP 200 且飞书业务 `code=0`，或管理员显式确认收到 |
| `failed` | 明确拒绝或限流在最多三次尝试后结束；重试退避为 1、4 分钟 |
| `delivery_unknown` | 网络超时、无法解析的响应或崩溃残留 sending，停止自动重发 |
| `cancelled` | 当前权限、配置、订阅或岗位失效 |

未知送达需管理员在站内记录中先核对群消息，再选择“确认已收到”，或“确认未收到，重试”。后者重用原 delivery，累计仍不超过三次。操作记录审计。不能把 HTTP 200 单独当作送达成功。

飞书签名、业务返回和消息约束依据[官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)，协议已用隔离 HTTP 服务验证；真实群行为尚未验收。

## API 与复验

本人路径在 `/api/v1/me`，对应管理路径在 `/api/v1/admin` 且必须显式传入 `owner_user_id`。所有写操作要求登录和 CSRF，revision 冲突为 409。

| 路径 | 方法与用途 |
|---|---|
| `/subscriptions` | GET / PUT 订阅；`filters_query` 为与看板一致的 URL 查询参数，`mode` 为 filtered 或 personalized |
| `/notification-channel` | GET 只读元数据；PUT 保存 write-only 凭据与 enabled/revision；DELETE 按 revision 清除 |
| `/notification-channel/test` | POST 排队固定连接测试，返回 batch_id |
| `/notifications` | GET 分页站内批次与发送记录，默认 20、最大 100 |
| `/api/v1/admin/automation` | GET 最近 30 个采集任务 |
| `/api/v1/admin/automation/collect` | POST `source_code` 排队手动更新，返回 task_id |
| `/api/v1/admin/automation/digest` | POST 为已启用订阅排队生成摘要，返回 task_id |
| `/api/v1/admin/notifications/{batchID}/resolve` | POST `decision=received` 或 `not_received`，处理未知送达 |

从项目根目录执行 `./scripts/verify-s4.ps1`，可传 `-NodeExecutable`、`-PnpmCli`、`-UseSystemProxy`、`-GoProxy`、`-HttpPort`。脚本使用随机 Compose 项目、专用 tmpfs PostgreSQL、合成资料和隔离浏览器账号；飞书请求由受控测试传输路由至本地 HTTP 服务，运行中的 API/worker 始终关闭真实发送，定时公开官网采集在测试环境关闭。不会使用本机账号或简历。

验收包含 Go vet、真实 PostgreSQL/Linux race、迁移、S2/S3/S4 电脑和手机浏览器、服务就绪与正常关闭。数据库测试跳过视为失败。结束后删除本次容器、网络和私有测试卷；本机数据库保留。日志和浏览器 trace 留在忽略的 `.cache/verification`，trace 可能含临时会话凭据，只用于本机排错。
