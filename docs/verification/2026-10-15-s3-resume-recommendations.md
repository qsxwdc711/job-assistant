# S3 简历与岗位匹配验收

日期：2026-10-15。范围：S3.1–S3.9 开发、本地处理、规则判断、隔离模型协议与网页验收。真实 DeepSeek 密钥由用户稍后配置，本轮未调用真实模型，不将模拟结果视为真实输出质量或费用验收。

## 交付行为

- VIP/admin 私有上传 PDF/DOCX，最大 10 MiB；校验文件签名、DOCX 解压总量和条目数。原文件使用随机键、私有文件权限与授权下载，不在网页目录中。
- 本地 Poppler / DOCX XML 提取，拒绝扫描空文本、损坏和加密文档；替换常见身份信息。用户可以修改脱敏预览，显式授权后才排队调用模型。
- JSON 草稿须经结构及原文引用校验，由用户确认生成不可变资料版本；同一账号选择一个当前版本。无密钥可手动确认并使用资格规则。
- 每个岗位方向单独计算学历、毕业范围、专业、明确经验要求、在校身份、实习月数与出勤。保留 eligible / needs_confirmation / ineligible；“优先”不作排除条件。
- 仅对非 ineligible 方向进行语义比较。高/中/低与资格结论分别显示，必需/优先/缺少证据分别说明，并保留资料与 JD 的逐字引用。
- PostgreSQL 任务、有限租约和三次外部尝试。调用前、回写前核验发起人与数据所有者权限、资料、岗位、方向、配置和租约。删除取消任务并通过删除发件箱重试物理文件清理。
- 缓存按账号与完整版本组合隔离。更换当前资料不修改既有投递关联；删除简历后投递与历史保留，资料关联置空。

## Go 功能与风格审查

应用 `go-feature-change-review` 和 `go-code-review`，按输入、转换、判定、执行和结果核对新增包、API、SQL、配置、部署和前端契约。

本轮发现并修复：

1. **解析接口与页面契约不一致。** 原接口将简历放在 task 字段，导致页面按简历 ID 轮询任务。现返回真实 task；HTTP 契约断言与完整浏览器流程验证修复。
2. **任务取消后状态可能长期显示 pending。** 补充取消状态回写及终态查询，失败/取消可重新提交，保持规则证据。
3. **最后一次已发布后宕机恢复可能重复处理。** 先识别已完成资源，再判断尝试上限；用真实数据库模拟结果已提交但队列未完成，恢复不产生第四次模型调用。
4. **相同 job_version 的岗位动态到期可能继续使用缓存。** 读取、再次生成和 worker 均检查当前截止状态，明确关闭后清除语义展示并停止外部调用。
5. **并发生成和大量历史版本边界。** 对同一所有者的入队事务串行化；缓存唯一键复用；当前版本优先于列表限额。分别通过并发和 105 条后续版本用例验证。

最终无未解决的必须修复项。未运行额外的 golangci-lint；已执行 gofmt、vet、Linux race、真实数据库和浏览器验证。没有创建后台每日采集或飞书业务，S4 尚未交付。
