## 行为覆盖

权限策略测试覆盖 12 个角色与资源场景。真实 PostgreSQL 集成测试覆盖 9 组行为：

1. 迁移幂等、校验和变更拒绝、两个初始化命令竞争只产生一个管理员和一条初始化审计。
2. VIP 到期时刻边界、授予和撤销后旧会话即时变化、停用删除全部设备会话、重新启用不恢复旧会话。
3. 会话令牌只存摘要、独立设备令牌、跨用户撤销返回 404 且目标会话继续有效、管理员撤销和会话精确到期。
4. 最后管理员的停用/降级拒绝，以及持有旧管理员对象时写入、账号读取和审计读取均拒绝。
5. 两名管理员并发自我降级，一次成功、一次被保护，最终保留一个启用管理员。
6. 审计表不可写时创建账号回滚，撤销 VIP 也回滚，既有会话仍读取原 VIP 角色。
7. 用户名大小写归一、唯一约束、错误凭证与未知账号统一失败、超过 bcrypt 上限的密码拒绝。
8. 三个独立浏览器客户端的真实 HTTP 流程：401、403、404、CSRF、VIP 撤销、停用、审计和退出。
9. TLS Cookie 属性、响应不泄漏令牌和密码、跨 Origin 拒绝、未知 JSON 字段、超大正文和登录限流。

## Go 功能与风格复核

按 `go-feature-change-review` 和 `go-code-review` 执行自审，读取入口、HTTP、服务、持久化、SQL、配置和实际测试，不使用代理代替独立运行证据。

已发现并修复的问题：

- **warning / security，旧管理员对象读取账号与审计。** 证据类型为 local_repro。输入：已降级管理员的旧 User；判断：服务只检查旧对象；执行：直接查询账号或审计；结果：仍返回数据。HTTP 每次重新认证是反证，但无法保护直接调用服务的其他调用方。新增测试先失败（`stale admin read accounts: <nil>`），然后在读取事务中重新查询操作者并加共享锁，账号与审计测试均通过。检查路径：identity/service.go、identity/store.go、integration/identity_test.go。后续任务仍需自己的执行前权限检查。
- **warning / tests，测试客户端共享 Cookie jar。** httptest 的客户端指针被多次复用，三个“浏览器”实际共享一个 jar，导致跨用户用例错误地以另一会话执行。改为每个客户端复制配置并创建独立 jar，真实 HTTP 越权测试通过。
- **warning / concurrency，事务清理与请求期限。** 复核中给回滚设置独立 3 秒期限，并为请求设置 15 秒上下文期限；数据库还有语句和锁等待上限。连接池、HTTP 服务和启动 goroutine 的关闭归入口所有。

最终复核未发现仍需修复的 S1 业务正确性问题。SQL 参数化；密码与令牌不进入公开 User 或审计；HTTP、服务、存储和策略职责分开；没有为后续模块创建占位业务接口或不必要的存储抽象。
