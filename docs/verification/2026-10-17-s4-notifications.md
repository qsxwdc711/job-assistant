# S4 定时更新与通知模拟验收

开发验收日期：2026-10-17；2026-10-18 继续交付收尾。范围：北京时间定时更新、个人订阅、站内摘要、加密飞书配置、持久化发件箱和电脑/手机操作。用户明确选择“先完成模拟验收，暂不发到真实群”，所以本机和隔离服务均保持 `NOTIFICATIONS_SEND_ENABLED=false`。协议测试使用受控 HTTP 服务，不绑定或访问真实机器人。

## 交付行为

每日 08:00 后按日期和来源幂等排队，最多三个实际读取且同域名互斥；CLI、手动排队和自动采集共享数据库锁。过期租约可恢复，旧 token 不能完成新租约，最多三次尝试。暂停、超时、崩溃和正常关闭均保留可核对状态，来源失败不清空已有岗位。

每日 09:07 生成截止快照；晚到版本进入后续摘要，失败或未完成来源显示在站内。普通账号使用保存的筛选，有效 VIP/admin 可使用当前资料的有效推荐，推荐缺失时不回退为普通结果。订阅/接收配置按账号隔离并用 revision 防覆盖。没有接收群也能保留站内摘要，没有事件不发送空消息。

飞书地址和签名密钥按用户 AES-256-GCM 加密，API 只读元数据。消息只含公开岗位投影，按截止/变更/新增排序，最多 10 个广告，最终 JSON≤18 KiB。HTTP 200 仍检查业务码；明确拒绝最多三次退避，模糊响应、超时或中断 sending 进入未知送达并停止自动重发。管理员可以显式核对未知送达并保留审计。

## Go 功能、风格与架构审查

应用 `go-feature-change-review` 和 `go-code-review`，核对输入 → 解析/投影 → 当前权限和版本判定 → 数据库或 HTTP 执行 → 站内结果。检查了新增 migration、task、notification、automation、catalog 读取锁/筛选、ingest 入口、API/worker、Compose 和前端契约。

发现并修复的行为问题：

1. **空队列时恢复写入被回滚。** `Claim` 先将过期的第三次尝试置失败或暂停任务置取消，随后无候选返回时曾回滚这些写入。现在空队列及域名竞争分支也提交清理事务；真实数据库用例直接断言持久终态。
2. **超时错误码与重试分支不一致。** 现有采集器返回 timeout_or_cancelled，调度最初只识别 timeout。现在统一接受既有错误码，测试真实队列退避和三次上限。
3. **任务领取与 CLI 缺少共享读取约束。** 只锁自动队列不能阻止 CLI 同时读取同域名。现实际采集入口持有共享 domain/global advisory lock，以零 HTTP 请求的反例验证。
4. **手动摘要持有外层账号锁再等待内层事务。** 改为每批在本事务重新检查管理员，外层先提交，真实队列生成用例通过。
5. **个性化推荐晚就绪会遗漏稳定旧岗位。** 改为按当前资料识别首次有效匹配，并保持事件唯一；新增真实数据库用例先生成 empty，再生成推荐，验证后续能出现机会。
6. **切换模式/资料可能重复截止窗口事件。** 截止键仅绑定 owner、岗位、明确截止和窗口，匹配事件仍保留资料范围；切换 filtered → personalized 后同一窗口仍只有一个事件。
7. **发送恢复与当前任务竞争。** 二次事务取得账号及 delivery 行锁后确认状态仍为 sending，避免已被恢复/处理的尝试继续发请求。先提交 sending，HTTP 不确定时保留 unknown，不隐式重发。

机械检查已执行；没有运行额外的 golangci-lint。实际调用、业务拒绝、网络模糊状态和取消路径由受控服务与真实数据库测试支持；不以模拟结果推断真实群已送达。
