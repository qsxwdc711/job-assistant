## 1. 浏览器问题已解决

原来运行的是 E 盘 Chrome 134，点击 C 盘程序仍会交给旧实例。经用户同意，正常关闭旧版窗口，再启动 C 盘程序；核对实际主进程的路径和版本，确认为 `C:\Program Files\Google\Chrome\Application\chrome.exe`、`155.0.8059.85`。

用户在 `chrome://inspect/#remote-debugging` 开启调试并完成浏览器连接授权后，连接成功。研究使用独立后台标签页；结束后关闭本轮两个岗位研究标签页，确认用户原有的 NCSS 首页与个人中心标签页保留，没有读取个人中心正文。

从 [NCSS 职位列表](https://www.ncss.cn/student/jobs/index.html) 的搜索框查询“软件”，使用页面提供的跳页控件。被动记录该页面实际发出的岗位列表响应，仅保留白名单岗位字段及读取元数据。详情、资源和页面自身的附属请求不计入下表的列表请求数。

| 验证项 | 实际结果 |
|---|---|
| 登录识别 | 页面显示退出入口；未提取账户名 |
| “软件”第 1、6、7、10、25 页 | 每页均 HTTP 200、业务 `flag=true`、10 条岗位 |
| “软件”第 1、6 页重复读取 | 两次的有序岗位 ID 与选定岗位字段均一致 |
| “软件”第 50 页 | HTTP 200、`flag=true`、0 条，界面无下一页 |

| 当前匿名对照 | 在同一浏览器中对第 6 页发送不携带会话凭据的只读请求，HTTP 200、`flag=false`，提示“请登录后查看” |

共记录 **9 次已登录岗位列表请求**，业务响应均成功；包含重复页和空结果，共返回 70 条记录，涉及 **50 个不同岗位 ID、33 个不同企业 ID**。这是抽查样本数；第 2–5、8–9、11–24、26–49 页未枚举，不能将其当作关键词结果总量或全站总量。不同企业 ID 也未按集团、分支或重复主体归并。

列表读取时间为北京时间 **16:44:48–16:48:01**；匿名对照与样本详情基本检查在 **16:49** 完成。精确 UTC 时间和所选字段的 SHA-256 见[结构化证据](sources/long-tail/2026-10-16-ncss-login-evidence.json)。哈希针对保留的岗位字段，不是完整含会话页面的响应哈希。

## 3. 为什么不能承诺“访问全部数据”

这次已证明登录会话解除第 6 页的匿名阅读限制。与此同时，有岗位页、空的第 50 页和随机无匹配查询，都返回 `count=500/total=50`。因此，**500 不是经过验证的真实匹配总量**，不能依据该计数判断采集完成。

本次看到的界面边界为 50 页；没有尝试绕过界面边界，也没有验证服务端第 51 页及以上的行为。第 50 页为空，不足以证明前面没有缺页、排序没有变化或所有匹配记录都已覆盖。

“软件”只是一个搜索条件，不能代表后端、测试、运维、安全、数据、嵌入式等全部计算机岗位。后续如用多个岗位词、地点、招聘类型等正常筛选提高覆盖，需要记录每个查询的覆盖范围，按岗位身份归并，并保留仍然未知的覆盖缺口。

本轮没有验证会话长期有效性、定时执行、限流恢复或适配器稳定性。当前结果属于**已登录人工会话中的读取验证**，不计为生产自动来源完成。
