## 1. 结论与当前覆盖

**公开采集技术验证结论：automatic_ready；正式自动接入仍未完成。** 已核实官方链接链、匿名列表与详情查询、完整实习岗位分页、三条真实岗位样本及独立重复获取。尚未实现项目采集器，也未完成连续 7 天调度验收，不能计入 20 家已自动接入数量。

- 应届生职位列表两次均为成功业务响应 `SUC0000`、`total=0`、`data=[]`。这是该招聘类别当前的有效空结果，不能解释为银行停止招聘或整个来源不可用。
- 实习职位列表两次均为 `total=19`，按官网默认每页 10 条完整取得两页，分别 10 条和 9 条；19 个 `publishGID` 不重复，两次身份集合一致。
- 核验两条计算机相关实习岗位：佛山分行的“业务条线数据分析实习生”“数字金融实习生”。另取一条多地点市场营销岗位作为排除对照，三条样本不能统称为三个计算机岗位。
- 当前校园公告列表为 4 条，公告存在不代表其下属岗位仍开放。呼和浩特、昆明公告仍可读取，但公告规定的投递截止日已过；东莞公告没有披露截止，不能推断开放。
- 当前并未取得其余 16 条实习岗位的详细条件，不能声称已经完整分类全部 19 条岗位。仅以名称判断计算机相关性也不足以判断用户可投递性。

## 2. 官方出处与获取依据

官方链为 [招商银行官网](https://www.cmbchina.com/) → 页面“人才招聘”真实链接 [招商银行招聘站](https://career.cmbchina.com/index.html)。两页本轮直接获取均 HTTP 200，分别耗时 692 ms、397 ms。官网同时保留指向 `career.cloud.cmbchina.com` 的校园招聘菜单；本报告采用已核实的“人才招聘”链，不声称其他链接均已验证。

招聘首页是 React JavaScript 壳，仅包含 `#root` 和“需要启用 JavaScript”提示。首页明确引用 `main.d37c8446.js`；该公开脚本给出路由、动态 chunk 名及 `/api` 请求前缀。随后仅读取实际引用的校园首页、职位列表、公告列表、公告详情和职位详情脚本，取得以下真实请求规则，未猜测接口。

CDP 前置检查显示本机 Chrome 未连接，Node 20.18.0 出现版本提示。沙箱内初次请求出现 DNS 解析失败，经只读网络访问审核后可正常访问。这些是执行环境限制，不是招聘网站的登录墙、验证码或关闭证据。本来源最终使用普通公开 HTTP 查询，无需浏览器渲染。

证据：[授权链与首页](samples/cmb-2026-10-14-authority.json)、[公开前端请求代码片段](samples/cmb-2026-10-14-public-contract.json)。前端静态文件名带构建哈希；将来应从实时首页发现资源，不把本次文件名写死为长期入口。

## 3. 列表、详情、分页及状态规则

### 3.1 实际公开查询

| 内容 | 官网实际路由与请求 | 参数及成功响应 |
|---|---|---|
| 校园主页 | `/campus/home` | 展示应届生与实习生两类入口 |
| 应届生列表 | `/positionlist/96574F8D-C7ED-4772-AE7C-BAC896D190C1` | 招聘类别 ID 来自校园主页，不等于毕业届数 |
| 实习列表 | `/positionlist/DF94FD6D-26D3-4A19-9E69-577C4BA1DE82` | 招聘类别为实习；不能直接继承 2027 校招公告规则 |
| 校园职位查询 | `POST /api/campusRecruitmentWebsite/job/getList` | JSON：`orgIdList`、`locationIdList`、`keywords`、`pageIndex`、`pageSize`、`recruitmentTypeId`；响应 `body.total` 和 `body.data` |
| 校园职位详情 | `GET /api/campusRecruitmentWebsite/job/getDetail?publishId=<publishGID>` | 列表身份字段为 `publishGID`，详情参数名为 `publishId` |
| 校园公告列表 | `GET /api/campusRecruitmentWebsite/notice/getList?pageIndex=1&pageSize=10&keywords=` | 公告身份为 `noticeId`，本次 `total=4`，一页完整覆盖 |
| 校园公告详情 | `GET /api/campusRecruitmentWebsite/notice/getDetail?noticeId=<noticeId>` | 页面 `/detail/school?id=<noticeId>` 展示 `contents` 正文 |

职位列表 POST 是查询操作。本轮没有调用 `jobApply`、注册、登录或简历接口。发送普通 JSON Content-Type 及前端公开使用的 `X-B3-BusinessId`，没有 Authorization、Cookie 或个人凭证。

分页按 `ceil(total/pageSize)` 取足，并核对实际记录数及身份去重。本次应届生 `total=0` 无需额外取页；实习两页共 19 条，公告一页 4 条。HTTP 200 还必须检查 `returnCode`；错误业务响应不能当作空列表。

匿名详情包含 `publishGID`、`recruitmentTypeID`、`jobCode`、`jobDisplay`、`jobResponsibility`、`jobRequirement`、`branchCode`、`branchCodeName`、`locationName`、`expiredOn`、`showJobAdjust`。列表提供 `location` 地点 ID；多地点为逗号分隔 ID，展示名称可能使用顿号，应拆为多个地点关联，保留原文。

推荐身份键为 `cmb + campusRecruitmentWebsite + publishGID`，同时保留招聘类别 ID 和招聘主体。`recruitmentTypeID` 是类别 ID，`jobCode` 不能当作毕业届数或批次年份。没有明确年度批次的实习记录保留批次未知；不要生成“2027 全职校招”的错误批次。

### 3.2 可核实的状态边界

- 两条技术实习岗位在本轮完整列表中，详情 `SUC0000`，官方日期为 `2026-12-31`，可以记录“核验时开放”。未实测登录后的真实投递成功，不能承诺用户一定可投。
- 日期字段只有日期，没有时间或时区。保留 date 精度和原始时区 unknown，不补造 `23:59:59`；在临界日发送截止提醒前补充时区依据。
- 历史具体校园职位 `B5D72E8D-C2D7-48EA-AC1A-217C96A0BA8F` 两次均返回 `EZPREC0001`、`该职位已过期, 请刷新后重试`，是该具体职位的明确关闭证据。
- 北京历史公告 `4B58639A-C643-475D-AB57-6B9E980040CD` 和武汉历史公告 `EA490799-1A8F-4DE5-A8C9-8A2F19FF06EA` 返回 `该公告已下线`。这只证明对应公告下线，不能关闭同一分行的所有岗位。
- `EZPREC0001` 本身不专门表示关闭；需结合具体 `errorMsg` 和请求对象。网络失败、解析错误、其他错误信息均进入核验异常，不能写成 closed。
- 本轮另查询社招“软件”关键词，成功返回 `total=0`。这只能说明该词的查询结果为空，不代表所有社招或计算机社招为空，尚未验证整个社会招聘来源。

投递入口使用 `/positionDetail/school?publishId=<publishGID>` 的具体岗位详情级别。页面有“立即投递”，公告说明需在线注册/登录后申请。本轮没有点击申请按钮，登录后流程未验证。

## 6. 采集器实现时的验收边界

1. 使用公开校园 API 取应届生与实习两种类别，逐页核对 total、记录数及身份键，再取目标岗位详情；公告抓取独立处理。每类空结果必须由成功业务响应支持。
2. 内容版本对岗位职责、条件、地点、日期与状态计算，忽略公告富文本样式与图片等装饰；招聘主体、优先条件、学生身份、出勤及未知笔试值保留到标准化结果。
3. 对本来源已经实际观察到的明确过期消息允许关闭相应岗位；公告下线只能更新公告状态。其他业务错误和列表突然缺失不能直接关闭岗位。
4. 公开页面和 API 可能变化；检测 HTTP 状态、业务码、结构、分页计数和关键字段漂移，失败时暂停发布新结果并留管理员核验。不得绕过之后可能出现的登录或验证码限制。
5. 验证完成只证明方法可重复。本项目的定时采集、差异入库、七天运行、用户推荐和飞书通知均尚未执行；当前没有新的云部署或费用承诺。
