## 2. 实际访问与重复验证

- 公开请求时间为北京时间 **2026-10-15 23:18:02–23:42:41**；审计使用 UTC ISO 时间。共 195 次 HTTP 读取尝试，151 次返回 HTTP 200、43 次传输失败、1 次 HTTP 400。HTTP 200 中包含登录限制和失效提示，不等于业务读取成功。
- CDP 浏览器未连接；本轮采用匿名 HTTPS 阅读公开 HTML、页面实际引用的 JavaScript 和前端公开查询接口。未操作用户浏览器或招聘账号。
- Moka 首次访问需要跟随同地址重定向，并在单次进程内接收网站正常下发的匿名会话 Cookie；没有保存 Cookie 文件或使用用户登录状态。单纯忽略响应 Cookie 会产生重定向循环。
- 单请求连接上限 10 秒、总时限 30 秒、响应上限 8 MiB。恢复后的 Moka 分页查询约每 2.5–3 秒一次，串行读取；传输失败与业务受限分开记录。
- 早期 Moka 批量探针出现连续 TLS 失败，失败审计保留。后续探针增加同域两次传输／服务端失败停止，以及 401/403/429 或业务登录限制停止；稍后单次试读恢复，再进行分页。探针改进不代表正式采集器已实现这些机制。
- 跨页列表不是事务快照。两轮总数、唯一 ID 集合和归一化内容一致，证明本次观察期内可重复；不能替代连续运行稳定性验收。

提交的证据只包含公开标识、少量事实字段、读取元数据和哈希；完整响应在本机忽略的 `.cache/research/long-tail/raw/`。不提交匿名会话值、前端响应格式所需的运行时参数、客户 API 密钥或招聘联系人的个人电话。

### 3.2 列表、详情和空结果

页面 `init-data` 包含企业、站点、首屏岗位和总数。前端实际使用两版查询接口：

```text
POST https://app.mokahr.com/api/outer/ats-apply/website/jobs/v2
POST https://app.mokahr.com/api/outer/ats-apply/website/jobs
POST https://app.mokahr.com/api/outer/ats-apply/website/job
```

这些 POST 均是公开读取查询，未调用投递、短信或账号修改功能。列表传入 `orgId/siteId/site/limit/offset/needStat`，详情传入 `orgId/siteId/jobId/locale`。分页 `offset` 是记录偏移量，实测步长 15；绿盟 13 页、韶音 14 页、深蓝互动 4 页，两轮均与总数匹配且跨页无重复 ID。

当前前端会对查询响应进行序列化封装；解码逻辑及参数均由公开页面和响应正常提供。本轮按页面实际算法读取，不猜测密钥或获取登录权限。两版前端资源的地址、时间和 SHA-256 均在请求审计中，不能把未承诺稳定性的前端查询当作永久 API 合同。

无匹配关键词测试在三站均返回业务 `success=true/code=0`、总数 0、岗位数组为空，属于可确认空结果。**未取得真实已关闭职位的对照**；列表缺失、查询失败和岗位关闭不得混同，关闭规则仍是生产接入验收项。

### 3.4 无法由单个接口列出所有企业

公开查询要求先知道企业与站点标识。另已读取 [Moka API 文档](https://www.mokahr.com/docs/api/index.html)，其中客户 API 使用客户范围的 API Key／认证方式，不是面向所有企业的公开目录。本轮没有调用客户接口，也没有取得全平台企业清单。

因此扩展方式应为：通过高校、公共就业、企业官网发现企业 → 核实企业官网与托管站的关系 → 将租户加入企业池 → 复用适配器。仍需逐企业保留授权链和健康状态。

## 4. NCSS：能够发现小企业，但匿名读取有明确边界

入口为 [国家大学生就业服务平台职位列表](https://www.ncss.cn/student/jobs/index.html)，页面前端实际调用：

```text
GET https://www.ncss.cn/student/jobs/jobslist/ajax/?jobName=软件&offset=1&limit=10
```

这里 `offset` 是从 1 开始的页码，与 Moka 含义不同。“软件”前五页两轮均为 50 个唯一岗位 ID；第六页起 HTTP 200 中返回 `flag=false` 和“请登录后查看”，不能继续按成功列表处理，也不能声称已获取网站全部职位。

分页返回 `count=100/total=10`，但随机无匹配词返回空数组时仍报告同样计数。因此不能将 100 视为真实总量，也不能仅靠空数组确认来源已无岗位。

| 样本 | 平台标示人数 | 验证结果 |
|---|---|---|
| [中科云教：互联网软件开发工程师](https://www.ncss.cn/student/jobs/QcxFRRcgoGHr1bNnoQgktZ/detail.html) | 50–99 人 | 专科及以上；详情只重复岗位标题，任职条件不足 |
| [重庆镓孪：软件开发实习生](https://www.ncss.cn/student/jobs/An7RZvkkBDLdeYcyXYoLRb/detail.html) | 1–49 人 | 本科及以上、计算机／电子信息；有真实开发职责；标题“实习”与类型“全职”冲突 |
| [重庆会凌：无线通信高级软件开发工程师](https://www.ncss.cn/student/jobs/72R9U9dvqzeqAsL78Do53J/detail.html) | 100–499 人 | 无线通信、研究生及以上，涉及 C/C++；不能忽略专业和学历要求 |
| [重庆蝉艺：UE 软件游戏地编](https://www.ncss.cn/student/jobs/38hQjN33LRZTutNRMcQz87/detail.html) | 1–49 人 | 实际为场景美术；专业字段混入职责，学历“不限”与详情“本科”冲突，作为分类反例 |

人数区间是平台资料，**不等于官方中小企业认定**。这些记录由高校或地方教育部门同步，平台的官方身份不能替代雇主官方来源；样本公司网址为空，投递按钮是站内功能，不能填造公司投递直达链接。

同一公司、同名职位可能由不同高校同步为不同岗位 ID，证据中保留重复候选及上游来源；不能仅凭标题自动合并，也不能重复推送。页面还包含隐藏弹窗和模板，正文中出现的其他公司名或“投递成功”提示不能误读为当前职位事实。

## 6. 后续接入顺序与必要规则

1. **先实现 Moka 两版公共页面适配器**，以已核实官方链的租户为首批。新租户仍需核对官方关系，不能因域名同为 Moka 自动放行。
2. **为高校／公共就业增加待核验企业池**，保存发现页面、平台企业 ID、企业名称、规模原文、公告／岗位日期和待核实投递链接；发现记录与正式广告分开。
3. **按岗位方向筛计算机职位**，同时保存企业行业。工业软件、制造业研发、金融科技和游戏开发也可能合适，不限于“互联网企业”。保留非技术反例与经验门槛。
4. **归并企业和重复线索后再监测**，保留多个上游来源；没有验证标识／链接对应关系时不直接合并职位。
5. **失败不清空、不下线**。分别处理成功空结果、匿名分页截断、登录限制、字段冲突、传输失败、明确失效；无证据的截止、毕业范围、笔试字段保持未知。

这些是由本轮证据得出的实施建议，尚未修改生产采集、权限、推荐或飞书推送流程。其他行业后续沿用企业发现、来源证据和适配器机制，再扩展岗位方向与资格规则。

仍需补验：Moka 真实关闭岗位、持续运行稳定性、雇主链未核实的小企业、高校不同模板的适配、生产限流／重试／去重／下线规则。NCSS 的匿名分页限制已经确认，不能作为等待网络恢复即可解决的事项。
