## 3. 单来源验证步骤

### 3.1 官方授权与当前入口

从公司官网、官方招聘公告或明确认证的官方渠道进入招聘页，记录最初出处和实际跳转后的完整网址。第三方 ATS 记录官网到 ATS 的链接链。搜索、论坛和高校转载用于发现线索，不能替代官方授权证明。

在招聘页定位当前批次及计算机相关岗位。保存入口核实时间、招聘主体、批次、是否公开访问和投递入口级别。

### 3.2 访问方式与限制

先读取公开 HTML/结构化数据，确认正文是否为已加载内容，而非只包含客户端模板。必要时用浏览器渲染查看列表、分页和详情。

只使用公开访问，不保存招聘平台账号、Cookie 或个人登录数据。遇到登录墙或验证码，记录受限点；不要把人工浏览成功等同于自动接口可用。

每条请求记录状态、耗时、来源和响应类型。受限及失败来源不进入正式自动来源数量。

### 3.3 最少样本和字段覆盖

每类至少采集三条有出处样本，优先覆盖：

- 明确毕业范围及学历要求的岗位。
- 多地点或分支主体的岗位。
- 截止/笔试未披露或者明确已截止的岗位。

保存实际存在的字段，缺失值记录为 unknown，不生成补充事实。样本仅作解析和规则验证，发布前必须独立检查开放状态。

| 字段组 | 必须验证的内容 |
|---|---|
| 身份 | 公司、招聘主体、来源岗位 ID 或稳定详情链接、招聘批次 |
| 岗位 | 名称、方向、职责、任职条件、招聘类型 |
| 资格 | 学历、专业、毕业范围、国内/海外口径、经验、学生身份 |
| 地点 | 国内地级市或海外国家/地区和城市，是否多地点 |
| 流程 | 笔试的明确 yes/no/unknown 及其适用范围 |
| 日期和状态 | 官方截止、原始时区、开放/关闭证据、最新核验时间 |
| 溯源 | 官方来源、授权链、投递入口与入口级别 |
| 变更 | 内容哈希、条件原文、标准化版本、抓取批次 |

### 3.4 重复、空列表与状态验证

至少两次独立获取同一来源，验证岗位身份键不随顺序或页面装饰变化。包含分页时必须能确认已覆盖所有目标页，而非只抓第一页。

空列表只有在明确的成功响应及完整分页证据支持下才能记为 valid_empty。HTTP 成功但正文是登录页/验证码/模板时不算空职位。

关闭证据必须来自明确截止、官方已结束状态或已验证的详情规则；暂时取不到详情不作关闭依据。通过保留的样本测试条件或截止变更是否能形成新版本。

### 3.5 维护和资源评估

记录该来源一次完整获取的请求数、耗时、浏览器使用情况、页面结构依赖、来源适配器和错误分类。只有定量记录后才估算 20 家每日任务的资源与费用。

明确哪些字段需要管理员核实、来源是否具有稳定 ID，以及页面结构变化后的检测方式。接入应支持暂停、重跑和失败追踪。

## 4. 来源结论

| 结论 | 定义 | 是否计入 20 家 |
|---|---|---|
| automatic_ready | 官方链已核实，方法可重复，列表/详情/分页可处理，关键字段及未知状态正确 | 计入实际实现并稳定运行后的数量 |
| restricted | 登录、验证码、访问授权或其他机制阻止稳定获取 | 不计入 |
| manual_only | 有官方依据，暂时只能由管理员维护，未证明自动完整获取 | 不计入 |
| invalid | 官方链无法证明、内容错误或不属于目标招聘范围 | 不计入 |

同一家公司允许多个源适配器，完成数量按公司集团去重。没有当前开放职位的公司，可以在证明自动来源可正常获取并返回有依据的空结果后计入跟踪数量，但开放岗位数单独统计。

automatic_ready 是技术验证结论，不代表某位用户满足岗位要求。后者由确认后的个人条件与岗位规则独立计算。

## 5. 每家公司证据记录格式

后续每个来源创建 docs/research/sources/<source-id>.md，并附必要的非个人化样本。该文件记录以下事实：

1. 验证日期、公司/招聘主体和当前批次。
2. 官方出处、授权链和实际招聘地址。
3. 获取方法、限制及为何选择该方法。
4. 列表、详情、分页、空结果和关闭状态的真实依据。
5. 三条样本的原始字段、标准化结果与缺失项。
6. 两次重复获取的时间、运行结果及身份键比对。
7. 请求数、耗时、浏览器资源和维护风险。
8. automatic_ready/restricted/manual_only/invalid 结论与证据。

不写“所有链接已验证”这类无逐项证据的总结，不保留含个人账户信息的响应。无法取得事实时记录具体失败结果，不猜测接口或截止日期。

## 6. 首阶段结束条件

腾讯、华为、招商银行三类来源都有能复查的官方链、真实详情样本与重复获取方法，足以决定第一批采集器和岗位字段。

上述首阶段条件本轮已完成。腾讯和华为没有取得真实关闭岗位对照，不新增未经验证的关闭规则；招商取得对应公告下线与具体职位过期响应。未知和异常状态的处理已写入设计与实施测试场景。

如任一来源受限，先明确受限机制和替代官方公开入口。不能解决时记录缺口并调整该来源的自动接入承诺，不用人工补录冒充自动接入。

之后进入应用基础开发，P1 来源按同一标准逐家扩充。20 家和连续 7 天的运行验收属于最终交付条件，当前文档不会提前标为已完成。
